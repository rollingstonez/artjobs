# 아트잡스와 모던아트잡스: 쌍둥이 사이트 개념

이 문서는 두 서비스가 **무엇이 다르고 무엇이 같은지**를 정한 기준 문서다.
히어로·문구·분야 코드·수집 소스처럼 두 사이트를 가르는 판단이 필요할 때 이 문서로 돌아온다.
사이트맵과 코드표는 `docs/SITEMAP.md`, 코드의 실제 정의는 `src/types/job.ts`(`FAMILIES`) 에 있다.

## 1. 경계는 파인아트 하나로 긋는다

| | 아트잡스 | 모던아트잡스 |
|---|---|---|
| 한 문장 | 파인아트 다섯 분야의 일자리 | 파인아트 밖의 모든 예술 일자리 |
| 분야 | 미술 · 음악 · 무용 · 국악 · 연극 | 실용음악 · 디자인 · 실용댄스 · 영화·영상 으로 시작. 웹툰·애니메이션·게임아트·광고·패션·상업사진 등 무엇이 와도 여기 |
| 목록의 성격 | **닫힌 목록.** 예술의전당·국립국악원·ARKO 우산. 새 분야가 들어올 일이 거의 없다 | **열린 목록.** 파인아트가 아니면 전부. 분야는 공고가 실제로 모이는 것부터 하나씩 켠다 |
| 코드 | `family = fine` | `family = modern` |
| 도메인 | artjobs.kr | modernartjobs.kr (예정) |

경계는 **아트잡스 쪽에만** 있다. 아트잡스에 속하는지만 판단하면 되고, 아니면 모던아트잡스다.

### 회색지대 판단 한 줄

> 예술의전당 무대나 전시장에 정기적으로 오르는가? 그렇다면 아트잡스, 아니면 모던아트잡스.

개별 결정(뮤지컬·오페라·창극·한국무용·서예·사진은 아트잡스, 디자인·영상연기·실용음악은 모던아트잡스)은 `docs/SITEMAP.md` 1장에 있다.
두 세계에 다 걸친 공고(뮤지컬 배우, 사진, 무대·촬영 기술 스태프 등)는 **저장은 한 곳에, 노출은 두 사이트에** 한다. 지금 있는 교차 노출(`GENRE_CROSSLINKS`) 규칙을 그대로 넓힌다.

## 2. 이름이 "모던아트"인 이유: 존중

디자인을 하는 사람도, 실용음악을 하는 사람도, 실용댄스·영상을 하는 사람도 스스로를 **아티스트**라고 여긴다.
사이트 이름은 그 정체성을 그대로 불러줘야 한다.

- 현장 은어나 별칭(딴따라, 판, 테이크, 세션, 크루 등)은 현장 느낌은 살리지만 그 사람들을 **낮춰 부르는** 느낌이 있어 쓰지 않는다.
- "순수예술 / 실용예술"이라는 말은 문서 안에서만 쓰고 **화면 문구에는 쓰지 않는다.** "실용"은 "순수보다 아래"로 들린다.
- 일반 사용자에게 "모던"은 미술 사조 이름이 아니라 "요즘의, 현대의"라는 뜻으로 읽힌다. 모던아트잡스는 "현대의 모든 예술 일자리"라는 뜻이다.
- 표기는 아트잡스와 짝이 맞게 **모던아트잡스**로 통일한다("모던아트잡" 아님). 코드 값 `modern` 은 이름과 무관하게 그대로 둔다.

## 3. 쌍둥이: 같은 뼈대, 다른 옷

### 같은 것 (뼈대)

| 항목 | 내용 |
|---|---|
| 두 원칙 | 내 집 근처 공고부터 · 연락처 비공개, 메신저로 소통 (`docs/SITEMAP.md` 0장) |
| 계정 | **하나.** 어느 쪽에서 가입해도 양쪽에서 쓴다. 조명 스태프가 극장 공고와 촬영장 공고를 한 계정으로 본다 |
| 기능 | 회원가입·프로필·인재정보·메신저·저장·지원·알림·공고 등록·마이페이지 전부 공통 |
| 분류 축 | 분야 · 장르 · 직무 · 게시판 네 축. 직무 6개(실연·창작·교육·기획·기술·보조)는 두 사이트가 같이 쓴다 |
| 상단 구조 | 게시판 종류(채용공고 · 오디션·공모 · 인재정보)가 상단, 분야 탭은 그 안에 |
| 저장소 · DB | 하나. 공고 행의 `family` 값으로 어느 사이트에 보일지 정한다 |

### 다른 것 (옷)

| 항목 | 아트잡스 | 모던아트잡스 |
|---|---|---|
| 분야 코드표 | `art` `music` `dance` `gugak` `theater` | 별도 코드표 (추가 예정) |
| 분위기 | 밝은 바탕 · 세리프 제목 · 미술관 도록 같은 여백 · 정적 | 어두운 바탕 · 굵은 산세리프 · 스튜디오·영화관 조명 · 동적 |
| 히어로 | 반 고흐 같은 저작권 만료 회화, 발레, 성악 장면이 천천히 지나간다 | 재즈, 촬영 현장, 실용음악·댄스 장면이 지나간다 |
| 수집 소스 | 예술단·미술관·공연장·재단·학교 (`scripts/crawler/sources.py`) | 제작사·스튜디오·에이전시·기업. 별도 대장 (추가 예정) |

"무대와 전시장 / 스튜디오와 스크린"은 **경계가 아니라 분위기를 설명하는 말**이다. 히어로·색·글꼴을 정할 때만 참고한다.

### 쌍둥이임을 보여주는 장치

1. **상단에 서로의 문.** 두 사이트 헤더에 "아트잡스 ⇄ 모던아트잡스"를 항상 둔다. 처음 온 사람이 형제 사이트임을 바로 안다.
2. **한 계정, 양쪽 통용.** 인재정보와 메신저도 양쪽에서 이어진다.
3. **회색지대 교차 노출.** 두 세계에 걸친 공고는 두 사이트에 다 보인다.

첫 화면 한 장으로 "여기는 어떤 예술의 집인가"가 읽히되, 상단의 문으로 "형제구나"가 3초 안에 보여야 한다.

## 4. 함께 키운다

같은 업계에 걸친 사람이 많다(반주자와 실용음악 강사, 무대 조명과 촬영 조명, 무대 배우와 영상 배우, 전시 디자인과 그래픽 디자인).
한 사이트의 회원이 다른 사이트의 공고를 자연스럽게 보게 되고, 기관·기업도 한 번 가입해 양쪽에 공고를 올린다.
두 사이트를 따로 홍보하는 게 아니라 **하나의 짝으로** 알린다.

## 5. 히어로 사진 원칙 (구현 시 지킬 것)

- 작가 사후 70년이 지난 회화(반 고흐·클림트·모네 등)는 자유롭게 쓴다. 메트로폴리탄미술관·시카고미술관·위키미디어 공개 자료.
- 발레·성악·재즈·댄스처럼 살아있는 사람이 찍힌 사진은 스톡(Unsplash·Pexels 무료 라이선스) 또는 직접 촬영분만 쓴다.
- **영화 스틸컷은 쓰지 않는다.** 대신 촬영 현장·슬레이트·조명 세팅·편집실 같은 "만드는 장면"을 쓴다.
- 알아볼 수 있는 유명 인물은 초상권 때문에 피한다.
- 모바일에서 히어로는 한 화면의 절반 이하. "내 동네 설정 바"가 그 안에 들어온다. 사진은 6~8초에 한 장씩 천천히 겹쳐 사라지고, 애니메이션 줄이기 설정에서는 한 장으로 고정한다.
- 사진은 WebP, 한 장 150KB 안팎, 사이트당 5~6장.

## 6. 순서

1. 아트잡스가 실제 수집 데이터로 먼저 돌아간다.
2. 코드 뼈대는 지금 같이 넣는다: 모던 분야 코드표, 도메인별 `family` 분기(홈·목록·검색·알림 조건), 브랜드(로고·문구·히어로) 분기.
3. 모던 수집 소스 대장과 robots 판정은 아트잡스 실데이터가 안정된 뒤 붙인다. 운영 부담이 두 배가 되는 지점이 여기다.
4. 직무 코드는 공통으로 두되, `stage_tech`(무대·기술) 라벨을 촬영·편집·사운드·모션그래픽까지 품도록 넓히거나 직무 하나를 더 두는 것을 검토한다.
